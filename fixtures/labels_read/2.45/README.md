# fixtures/labels_read/2.45: official labels saved for ticket 2.45

Every entry that ticket 2.45 adds to `moonlight/corrections.json` (a red
warning) is backed by labels saved in this folder. Fetched on 2026-11-25
from DailyMed (current labels through the DailyMed web service; a card's own
link that DailyMed has since retired was read from its web page). Each `.txt`
file holds, in this order:

1. the link of the label that was read first (line 1),
2. the date (line 2),
3. the product name line,
4. the whole INDICATIONS AND USAGE section, word for word.

Some files then hold more labels, each starting with a line
`== another label read: <link>`: other brands or forms of the same medicine,
including the labels that name the disease in some other way (a cause, a
setting, an exclusion, a warning, "not effective"). Only the spacing was
tidied (one line per paragraph, list item or table cell). No word was
changed. Where a label's section carried no heading line, the line
`INDICATIONS AND USAGE` was put on top (the section's own name).

Each row below is one card. The quoted sentence is the label's own sentence
about what the medicine IS for. The disease words are in the saved text
(`The disease named` notes below the table list where). These entries are
proposals until MAIN 3 has read the saved label text.

How the search was done: for each medicine, every label DailyMed lists under
its name (every brand and form, combinations too) was opened and its
indication section read by code for the disease words, where DailyMed lists
up to 130 labels. For the big generics (hydrochlorothiazide, prednisone and
so on), openFDA's label search was used as a pointer to the labels whose
indication text names the disease words, and the hits were read by hand.
A machine pointed; a person read the hits.
